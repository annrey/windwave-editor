## Title

`v0.2.0: closed-loop execution and correctness fixes`

## Labels

`enhancement`, `priority:high`, `area:agent-core`, `area:bevy-adapter`, `area:qa`

## Body

WindWave v0.2.0 should stop expanding surface area and focus on making the existing editor loop reliable:

`user request -> plan -> act -> observe -> revise -> verify -> undo`

### Scope

- Wire the real ReAct/DirectorRuntime execution path deeply enough that a user request can produce Bevy scene changes.
- Add an acceptance path for: "创建一个红色敌人放在右边".
- Ensure the result is observable through SceneIndex.
- Ensure the generated operation can be undone.
- Fix correctness issues that would make the loop unreliable:
  - SceneIndex deleted-entity residuals.
  - Missing or unclear reverse contracts for write-type `EngineCommand`s.
  - HR add/remove/fire approval UI smoke.
  - Scattered keyword routing that causes inconsistent planner behavior.

### Acceptance Criteria

- Running the red-enemy QA path creates a new enemy-like entity.
- The entity has a red visual component or command trace.
- The entity is placed to the right of the origin or the target entity.
- SceneIndex observes the new entity after the command is applied.
- Undo removes or reverts the created entity.
- Failed execution produces a revision/reflection path instead of silently stopping.
- `cargo build` passes.
- `cargo test --workspace` passes.
- `cargo clippy --workspace -- -D warnings` passes.
